# AI analysis

A [micro-agent](/control/estudio/microagentes) assigned to a [rule](/bandeja-inteligente/reglas-de-correo) reads each email the rule captures and generates an analysis: a summary, the key data, pending actions… Analysis uses credits.

The analysis covers the sender, recipients, subject, date and body of the email. Attachments are not part of the analysis.

## The two types of analysis {#los-dos-tipos-de-análisis}

| | Mail Reader | Email to Markdown |
|---|---|---|
| **What it generates** | Structured data: summary, signals, entities, pending actions… | A text document with the email's content, ready to save |
| **Where it is saved** | If the rule has a **Summaries folder**, one file per email, in monthly subfolders | Wherever you choose, with **Save to Knowledge Hub…** |
| **What it is for** | Reviewing and classifying emails, following up on orders or incidents | Turning emails into knowledge that agents can consult |

## Analyze an email {#analizar-un-correo}

1. Open the email and click **Show AI panel**.
2. Click **Analyze and save** (if the rule has a summaries folder) or **Analyze with AI**.
3. The analysis takes a few seconds. You can keep browsing; the result appears in the panel.

You can also start it from the sparkles button in the email list.

The panel tells you when an email cannot be analyzed and why, for example:

| Message | What to do |
|---|---|
| **This email matches no active rule with a micro-agent.** | Create or adjust a rule, or assign it a micro-agent |
| **The rule that matches this email is disabled** | Enable it |
| **The rule has no summaries folder** | The analysis is shown but not saved. To save it, **Choose a summaries folder in the rule** |

## Analyze many emails at once {#analizar-muchos-correos-a-la-vez}

**Analyze pending** processes in a batch the emails of a rule that do not have an analysis yet. It is in the rule's **View details** (**Manual processing**) and in the list header when you filter by a rule with a micro-agent and a summaries folder.

- It analyzes up to 50 emails per run.
- By default, from the last 7 days, or from the rule's **Capture emails since** date.
- When it finishes, it shows how many were analyzed, how many were already saved, how many failed and how many are still pending. To continue, **Process again**.
- It stops if you run out of credits.

## The result {#el-resultado}

With a **Mail Reader**, the panel shows the result organized:

| Section | Content |
|---|---|
| **Summary** | The email in a few lines |
| **Signals** | **Urgency**, **Sentiment**, **Intention** and **Language** |
| **Sender** and **Recipients** | Who is writing and to whom |
| **Detected entities** | Names, companies, amounts, dates… |
| **Pending actions** | What the email asks to be done, with its priority |
| **Tags** | Suggested classification |

The sections depend on the micro-agent's response schema. The result is generated by AI and may contain errors.

With **Email to Markdown**, the panel shows the **Generated document** and the **Save to Knowledge Hub…** button to choose the folder.

## Analyze again {#volver-a-analizar}

**Analyze again** generates a new analysis that replaces the previous one, including the saved file. It uses credits again and cannot be undone. If an analysis failed, **Retry and save** tries again.

## Credits {#créditos}

Each analysis uses the organization's credits, except with the organization's own models. Opening an email or viewing an existing analysis does not use credits. With no credits left, the panel says so, with a **View usage** link.

## Best practices {#buenas-prácticas}

:::tip Useful analyses
- Assign a micro-agent only to the rules whose emails need analysis: each analysis uses credits.
- For classification or follow-up, a **Mail Reader** with a summaries folder: summaries are kept organized by month and can be shared with an agent.
- Try a few emails one at a time before using **Analyze pending**.
:::
